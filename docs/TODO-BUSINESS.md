# Heros — 商业场景说明（集体 + 全员 agent）

本文档说明：**游戏 / 电商 / 通用企业**场景下，当前系统与「管理员集体 + 员工各装 agent、自动同步技能与记忆」这一商业愿景的对应关系。与 `TODO.md`（技术现状与工程待办）互补。

## 你想要的模式（理想形态）

| 角色 | 做什么 |
|------|--------|
| **管理员 / 集体节点** | 在一台工作站上跑「集体」服务，汇总、审批、分发组织级知识 |
| **每位员工** | 各自机器上装 **agent**，日常做游戏/电商/通用业务辅助 |
| **集体** | 从各员工 agent **同步技能、记忆、进度**，形成组织大脑 |

## 现在实际上能不能这样工作？

**不能按「完整产品」那样工作。**  
可以把它理解成：**本地智能体控制面已经比较完整，但「多机集体 = 共享技能与记忆」这条链路只有桩，没有成品。**

### 今天已经能支撑的业务价值（单机 / 小团队）

- **每台机器**：`agentd` 长期跑，**技能 / 工具 / 系统提示 / 会话记忆**在本地目录里，经审批更新；适合 **个人生产力、小团队各自一套数据目录**。
- **企业栈（可选）**：接上 Neo4j / Qdrant / NATS 后，**单节点或中心化部署**可以做向量检索、图、事件，**不是**自动多工作站合并。
- **集体相关**：配置了 `collective_url` 时，主要是 **把「提案」HTTP 推到 `collectived`**，以及 NATS 上发 **提案类事件**；**没有**「把各员工磁盘上的技能树和记忆库持续同步到集体再下发」的完整机制。

### 和游戏公司 / 电商公司场景的对应关系

| 你想要的 | 游戏 / 电商公司场景 | 当前系统 |
|----------|---------------------|----------|
| 管理员一台跑集体 | 主控台汇总全组知识 | `collectived` 只是**示例**：收提案、可选发 NATS；**不是**成熟的集体后端 |
| 员工各装 agent | 策划/程序/美术各自助手 | **可以**：每人 `agentd` + `data_dir`，本地学习与辅助 |
| 集体同步 **技能** | 共享管线、规范、工具用法 | **未实现**：无自动跨机合并/版本/冲突解决；只有提案**信号**可上送 |
| 集体同步 **记忆** | 项目共识、决策、进度 | **未实现**：记忆主要在**本机**（+ 可选本机/中心 Qdrant）；**没有**「全员记忆上收再分发」的产品化流程 |
| 集体同步 **进度** | 里程碑、任务状态 | **未实现**：需自建任务/项目管理集成，本仓库不自带 |

**小结**

- **「每人类似装一个会学习的本地 agent」** —— **方向对，单机层面 largely yes**。  
- **「一台集体汇总全员技能+记忆+进度」** —— **现在 no**，需要集体侧补全协议与服务。

## 一句话结论（英文可对外）

**Does this system work like this now?** — **No.** 它**不是**现成的「管理员集体 + 全员 agent 自动同步技能与记忆」的商业套装；它是 **本地 agent 运行时 + 审批式演进 + 集体/NATS 的扩展点**。  

**Any kind of company**（游戏、电商、通用）都一样：**单机/单租户用法可行**；**多机组织级知识池**需要额外产品化（集体存储、同步、权限、冲突与审批），当前仓库**没有做完**。

## 若向老板 / 客户讲的「商业方案」怎么说才诚实

1. **Phase 1（现在就能卖 / 能试点）**：每岗位或每项目 **独立 agentd**，统一策略与技能包（用 Git / 内部分发目录代替「集体」），记忆默认**不跨人**或只共享**经审批的文档/技能**，满足合规。  
2. **Phase 2（要开发）**：在现有 **提案 + NATS** 之上，做 **集体服务**：技能/记忆的 **push/pull、租户隔离、版本与审批**，再接到各工作站的 `agentd`。  
3. **垂直行业**（游戏 / 电商）：差异主要在 **你们提供的技能模板、工具集成、记忆结构**，而不是当前二进制里已写死的行业逻辑——**行业包是配置与内容问题**，**集体同步是平台能力缺口**。
