## runtime-invocation

A runtime invocation is a distinct concept from a static node definition (Decision 1, design.md). It is an execution instance that references a definition by node_id. A single definition MAY correspond to many invocations in one run (a loop firing 7 times => 7 invocation records, one definition). Kept separate so node count stays per-definition and the graph stays diffable.

| Field | Type | Required | Meaning |
|---|---|---|---|
| `invocation_id` | string | yes | Unique id for this single execution instance |
| `invocation_index` | integer | yes | 0-based index of this invocation among the definition's invocations within the run (e.g |
| `node_id` | string | yes | References the static definition's node_id in the Workflow IR. |
| `run_id` | string | yes | Groups all invocations of one execution batch |

## workflow-ir

The canonical intermediate representation of a discovered LLM workflow: a versioned graph of static node definitions and typed edges. Emitted by Discovery (P1); consumed by the Config Layer (P2), Pattern Classifier (P3.5), Eval (P4), Re-arrangement (P5), and the graph UI. Frozen at M0. See docs/prd/P0-foundations.md and openspec/changes/p0-foundations.

| Field | Type | Required | Meaning |
|---|---|---|---|
| `declared_env` | array | no | Optional (P10, additive) |
| `edges` | array | yes | Typed edges between static node definitions. |
| `ir_version` | string | yes | Semver of the Workflow IR schema |
| `nodes` | array | yes | Static node definitions |
| `subgraphs` | array | no | Optional |
| `workflow` | object | yes | Identity of the source workflow the IR was extracted from. |
